## Defects found

1. **The registered skill description advertised a state that no longer exists.**
   `"walk, daydream, dissociate, dream, doomscroll"` — `dissociate` was retired and
   `unstuck` was missing. This is the text a person reads in the skill list. Fixed.
2. **A fresh install showed an empty card.** `surfaces.art` read only
   `<data>/three_frames/`, which does not exist until someone runs the bake, so a
   new install got a blank rectangle for every state. Fixed by shipping one 400×105
   frame per state in `assets/frames/` (`tools/make_fallback_frames.py`, 56 KB
   total) and falling back to it when the data dir has no frames.
3. **The documented takeover did nothing.** `python3 -m core.tui` had no
   `__main__` block: it imported the module and exited 0 with no output, in every
   home. README, TESTING and the demo script all name this command. Added an entry
   point.
4. **The takeover drew nothing when the terminal reports 0×0.** A pty without a
   window size (and some tmux/ssh cases) produced a zero-width grid: alt screen,
   hidden cursor, no picture. Size is now clamped to at least 40×12.
5. **The renderer printed `THREE.SoftwareRenderer 82` into the frame.** The
   software renderer logs at require time and stdout is the frame channel, so the
   line landed in the middle of the takeover. Silenced around the require.
6. **A mistyped tool action returned the status picture.** `state(action="frob")`
   fell through to `panel.render`, so a model that guessed got art instead of an
   answer. It now returns `no such action: 'frob'. try: …`.
7. **The suite went red in a working tree with experiment output.** The
   retired-name test exempts recorded model output under `evaluation/results` but
   not `experiments/*/{*.json,*.jsonl,*.html,*.log}`, which is the same thing — a
   scene set in a domestic room appears in those answers. A clean clone passed;
   a developer's tree did not. Exemption widened to recorded output only.

## Not defects (checked, behaved)

- Open states leave tools alone; blocked states refuse and name `/return`.
- Expiry/`complete` paths, journal, residue and account wording match `docs/spec.md`.
- No model call on entry, card or exit.
- Writes stay inside `ANTEMUSE_STATES_HOME`.
- `hermes plugins doctor` and `validate` pass at this commit.

## Known limits that remain

- `unstuck` has no art of its own and renders the walk frame; stated in the README.
- The desktop dock pane is built but was not confirmed inside the packaged app.
- Doomscroll keeps its tools open by design; entering it with `block: true` is the
  only way to close them.
- The takeover was verified in a pty, not in a real GUI terminal emulator; cursor
  and colour behaviour on a physical display is unverified.

## Found after the pass: the security scan reads the evidence files

`hermes plugins validate` used to report `warnings: []` on this tree. It now
reports 36 caautions, all from one place: the tracked experiment transcripts
(`experiments/before-after/results-*.json`) contain recorded model answers that
say things like "imagine you are…" and the scanner flags those phrases as
`role_pretend` / `conditional_deception`.

- Scope: 16/16 checks still pass, `ok: true`. These are cautions, not failures.
- Cause: the scanner reads data files as if they were plugin source; the phrases
  are quoted model output, not instructions the plugin gives.
- It is not a leak of live secrets and nothing executes these files.

This needs an owner decision, not a silent fix: either the transcripts stay (and
the submission says plainly that validate reports cautions on recorded evidence),
or the recorded transcripts move out of the plugin repo into the evidence archive
the way the generated art did, and the spec/README point at the archive. Removing
them is easy; it is also removing the public evidence for the before/after claim,
so it should be Ryan's call.
