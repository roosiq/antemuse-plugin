# Product specs

Durable statements about what Antemuse is, kept apart from individual change records.

| file | answers |
| --- | --- |
| `positioning.md` | What the plugin is for, the words it uses in public, and what it does not claim. |
| `states.md` | The one agent state, separate person-driven explore mode, and their contracts. |
| `examples.md` | The generated walk and explore examples a stranger reads before installing. |

Related material:

- `docs/design/` — visual and interaction design.
- `docs/design/APP_FLOW.md` — the drawn state lifecycle.
- `specs/changes/` — active change records and acceptance evidence; superseded records live under
  `specs/changes/historical/`.

If a product spec and the code disagree, the spec is stale until proven otherwise.
